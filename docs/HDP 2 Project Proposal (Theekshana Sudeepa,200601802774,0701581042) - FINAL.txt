Document Purpose
This document is meant for Oridil Solutions (hereafter referred to as the Client).
The copyright of this document rests with Thikka Solutions (hereafter referred to as Thikka Solutions) and no part of the same should be copied without consulting with the same.
The document outlines our understanding of the project requirements, the objectives of the M-commerce solution, the methodology, deliverables, and commercials. It serves as a comprehensive project proposal for the development of LexoraFix, a mobile commerce application designed to address the real-world challenge of providing a unified digital platform for purchasing home improvement tools and booking professional home maintenance services in Sri Lanka.

Client Brief
The client requires a fully functional M-commerce Android application that addresses the following real-world problem:
Problem Identified: Homeowners and DIY enthusiasts in Sri Lanka face difficulty in finding a single, reliable platform to both purchase home improvement tools and book professional services (installation, repair, maintenance) for their homes. Current solutions are fragmented, leading to poor user experience, lack of transparency in pricing, and difficulty in tracking orders and service requests.


Client Requirements
1. Customer-Facing Mobile Application → A modern, responsive Android app allowing users to browse and purchase home tools and accessories, and book professional home services.
2. Separate Admin Application → A dedicated administrative panel for managing products, categories, orders, bookings, users, and viewing business analytics.
3. Secure Payment Integration → Integration with PayHere, Sri Lanka's leading payment gateway, supporting multiple local payment methods (Visa, MasterCard, eZ Cash, mCash).
4. Real-Time Data Synchronization → Cloud-based data storage ensuring that orders, bookings, and product information are synchronized in real-time between customers and administrators.
5. Location-Based Services → Integration of maps to display nearby service centers and capture user location data during service bookings.
6. Notification System → Automated notifications for order confirmations, status updates, and booking alerts for both customers and administrators.
7. Multi-Authentication Support → Secure login through email/password and Google Sign-In for convenient on-boarding.
8. Sensor Integration → Utilization of device sensors (accelerometer, GPS) to enhance the user experience through innovative interaction patterns.
9. Multimedia Support → Product demo video playback and image galleries for enhanced product showcasing.
10. Telephony Integration → Direct phone call capability to service centers from within the application.

Scope of Work
Objective

Purpose and Scope: LexoraFix is designed as a comprehensive M-commerce platform that combines product commerce (home tools, hardware, accessories) with service commerce (professional installation, repair, and maintenance services). The primary goal is to create a one-stop digital solution that bridges the gap between home improvement product retail and professional home services in the Sri Lankan market.

Key Features: Product browsing by category with search and filtering, shopping cart with quantity management, secure PayHere payment processing, service booking with date/time scheduling and GPS location capture, real-time order tracking with status timeline, interactive maps with service center markers, user profile management, Google Sign-In authentication, shake-to-cart sensor feature, product demo video playback, and direct phone call to service centers.

User Experience: Material Design 3 components throughout, gradient-based visual hierarchy, responsive layouts with 6 breakpoints (sw320dp to sw720dp + landscape), status bar integration with fitsSystemWindows, dark-themed admin panel, micro-animations and smooth transitions, empty state designs with visual CTAs.

Security: Firebase Authentication for secure identity management, Firestore Security Rules for server-side access control, PCI-DSS compliant PayHere payment processing, BuildConfig secrets management with local.properties, runtime permissions for location/phone/notifications.

Business Impact: Unified platform eliminates need for separate apps, real-time Firestore sync reduces response times, local payment methods lower purchase barriers, GPS-based service discovery improves logistics, automated email and in-app notifications reduce support burden.

Administrative Panel
The LexoraFix Administrative Panel is a separate Android application module (com.lexoratech.lexorafix.admin) providing a comprehensive interface for managing all operational aspects of the platform.

User Roles and Permissions
Role-Based Access Control (RBAC) → Only users with role: admin in Firestore can log into the admin app. Firebase Authentication provides the shared auth system between customer and admin modules. Firestore Security Rules enforce admin-only write operations server-side.

Dashboard and Analytics
The admin dashboard displays real-time statistics including Total Users, Total Orders, Total Bookings, Total Products, Total Categories, and Total Revenue (LKR). Glass-effect stat cards with gradient backgrounds provide a premium appearance. Quick action buttons enable one-tap access to add products, manage orders, and view bookings.



Product Catalog and Inventory Control
Administrators can add, edit, and delete products with fields for name, description, price, stock quantity, category, and image URL. Product status toggle enables products to be disabled without deletion. Stock is automatically decremented when customers place orders. Categories can be added, edited, and deleted independently.

Order Processing
The order management screen displays all customer orders with customer name, email, item details, and payment status. Administrators can update order status through the progression: Confirmed → Processing → Shipped → Delivered / Cancelled. Status changes are reflected instantly on the customer app via Firestore real-time listeners.

Service Booking Management
All service bookings are displayed with customer details, service type, scheduled date/time, and notes. Customer GPS coordinates or geocoded addresses are shown on each booking card. Booking status can be updated with real-time sync to the customer side.

Customer Account Management
Administrators can view all registered users with their name, email, and role. User profiles and associated order/booking history are accessible from the admin panel.

Process Flow
Customer Application Process Flow
Step 1: User launches the app → Splash Screen with animated logo
Step 2: Auto-redirect to Login screen (if not logged in) or Main screen (if session exists)
Step 3: Login via email/password or Google Sign-In → Firebase Authentication → Firestore profile fetch → SharedPreferences session save
Step 4: Main screen with Bottom Navigation (Home, Categories, Cart, Services, Profile)

Shopping Flow
Step 5: User browses products via Home (featured products) or Categories (filtered grid)
Step 6: User can search products by name or filter by price range/sort order via bottom sheet
Step 7: User taps product → Product Detail screen (image, description, price, stock, demo video)
Step 8: User adds product to cart → SQLite persisted cart with quantity management
Step 9: Alternative: User shakes device → Accelerometer sensor detects shake → Cart opens automatically
Step 10: User proceeds to Checkout → enters delivery address → reviews order summary
Step 11: PayHere payment SDK launches → user completes payment → callback received
Step 12: Order saved to local DB + Firestore (dual-write to user subcollection and top-level orders collection)
Step 13: Product stock decremented in Firestore for each ordered item
Step 14: Email sent to customer (order confirmation) and admin/seller (full order details)
Step 15: In-app notification shown to customer
Step 16: User views order in Order History → taps Track → Order Tracking timeline (Confirmed → Processing → Shipped → Delivered)

Service Booking Flow
Step 17: User navigates to Services tab → selects service type (Installation, Repair, Maintenance)
Step 18: User taps Book Service → fills form (date, time, notes)
Step 19: GPS location captured via LocationManager → geocoded to address
Step 20: Booking saved to local DB + Firestore (dual-write)
Step 21: User can view Map → interactive Leaflet.js map with service center markers and user location
Step 22: User can call service center directly via phone call intent
Admin Application Process Flow

Step 1: Admin launches admin app → Login screen
Step 2: Firebase Auth login → Firestore role check (must be role: admin) → Dashboard
Step 3: Dashboard displays real-time stats (users, orders, bookings, products, categories, revenue)
Step 4: Admin uses Quick Actions to navigate to management screens
Step 5: Manage Products → Add, edit, delete products with image, price, stock, category
Step 6: Manage Orders → View all orders with customer details → update status → real-time sync to customer
Step 7: Manage Bookings → View all bookings with customer location → update status
Step 8: Manage Users → View registered users with profiles

Data Flow Architecture
Customer App ↔ Cloud Firestore ↔ Admin App (real-time listeners for bidirectional sync)
Customer App → SQLite + SharedPreferences (local persistence)
Customer App → PayHere SDK (payment processing)
Customer App → Gmail SMTP via JavaMail (email notifications to customer and admin)
Customer App → LocationManager (GPS for maps and bookings)
Customer App → Accelerometer Sensor (shake-to-cart feature)
